# Tactiq

**Код бич. Бүтээ. Ирээдүйгээ зохио.**

Хүүхдэд код бичих чадвар, логик сэтгэлгээг тоглоомжуулсан хичээлээр
сургадаг платформ. Сурагчийн вэбсайт болон **Хяналтын самбар нь НЭГ Next.js
төсөл** — ижил өгөгдлийн сан, ижил нэвтрэлт, ижил компонентын сан дээр
ажиллана.

## Технологи

| Давхарга | Сонголт |
| --- | --- |
| Framework | Next.js 16 (App Router) + React 19 |
| Хэл | TypeScript (strict) |
| Загвар | Tailwind CSS v4 |
| Өгөгдлийн сан | PostgreSQL, Drizzle ORM |
| Нэвтрэлт | Firebase Authentication (+ Admin SDK-аар сервер талд шалгах) |
| Дүрс | lucide-react |

Гуравдагч талын график, дата-fetch, огнооны сан ашиглаагүй — эдгээр нь
клиент бандлыг тэлэхээс өөр зүйл өгөхгүй хэмжээний хэрэгцээ байсан.

## Бүтэц

```
src/
├── app/
│   ├── (site)/            Нийтийн вэбсайт — нүүр хуудас (нэвтрэхгүйгээр)
│   ├── (auth)/            Нэвтрэх, бүртгүүлэх, эрх дууссан
│   ├── (app)/             Сурагчийн апп — хичээл, зорилго, амжилт, төсөл
│   ├── (lesson)/          Хичээлийн тоглуулагч (өөрийн бүтэн дэлгэцтэй)
│   ├── admin/             Хяналтын самбар
│   └── api/               Бүх өгөгдлийн үйлдэл
├── components/
│   ├── tactiq/            Сурагчийн UI
│   └── admin/             Админы формын элементүүд
├── context/               Хэрэглэгч, сэдэв, хажуу цэс
├── lib/
│   ├── api/               Зөвхөн сервер тал (эрх, дүгнэлт, хэмжигдэхүүн)
│   ├── tactiq/            Домэйн логик (оноо, дараалал, дүгнэлт, өнгө)
│   └── db/                Drizzle схем ба холболтын сан
└── hooks/
```

### Аюулгүй байдлын гол зарчим

Дасгалын **зөв хариулт клиент рүү ХЭЗЭЭ Ч явахгүй.** `/api/courses/…/lessons/…`
route нь дасгалыг `toPublicExercise()`-ээр цэвэрлэж, `answer` талбарыг
таслана. Дүгнэлт бүхэлдээ `src/lib/tactiq/grade.ts` дээр, сервер дээр хийгдэнэ.
Оноо, эрдэнэ, дараалал бүгд сервер талд тооцогдоно — `/api/users/me`-ийн
PATCH нь эдгээр талбарт бичих боломжгүй.

Клиент талын `<Protected>` хамгаалалт нь зөвхөн ТАВ ТУХЫН зорилготой.
Жинхэнэ хаалт нь API route бүр дэх `requireActiveUser` / `requireAdmin`.

**Хяналт** (`admin` эсвэл `super` эрхтэй)

| Зам | Тайлбар |
| --- | --- |
| `/admin` | Идэвхийн график, хамгийн хэцүү дасгалууд, шинэ сурагчид |
| `/admin/courses` | Курс үүсгэх, засах, нийтлэх |
| `/admin/lessons/[id]` | Онолын алхам ба дасгал засварлагч |
| `/admin/achievements` | Тэмдэг үүсгэх, босго тохируулах |
| `/admin/users` | Эрх, төлөв удирдах, хайх, шүүх |

**Багш** (`teacher` эрхтэй) **ба эцэг эх** (`parent` эрхтэй)

| Зам | Тайлбар |
| --- | --- |
| `/teacher` | Миний сурагчид — сурагчийн кодоор нэмэх, ахиц/оноо/дараалал харах, холбоос салгах |
| `/parent` | Миний хүүхдүүд — яг ижил үйлдэл, зөвхөн үгсийн сонголт өөр |

Сурагч (`student`) өөрийн профайл хуудаснаас (`/profile`) хувийн кодоо
харж, эцэг эх/багшдаа өгнө.

**Холбоосын загвар** (`student_links` хүснэгт, `lib/api/studentLinks.ts`):

* Насанд хүрэгч ↔ сурагч нь **олон-олон** харьцаа (нэг хүүхэд ээж, аав,
  багштай; нэг багш олон сурагчтай) тул `users` дээрх багана биш, тусдаа
  хүснэгт.
* `relation` (`"parent" | "teacher"`) нь холбоос үүсэх мөчийн үүргийг
  **хөлдөөнө**, `users.role`-оос ТУСДАА. Учир нь нэг хүн эцэг эх БА багш
  хоёулаа байж болно (`users.secondaryRole`) — тэр хүн өөрийн хүүхдийг
  `parent`-аар, ангийнхаа сурагчдыг `teacher`-ээр хөтөлнө. `role`-оос
  гаргаж авбал хоёр жагсаалт хольцолдоно.
* ⚠ **Холбох route нь rate limit-тэй** (IP тутам 10 мин/10 оролдлого).
  Урилгын код нь 6 тэмдэгт (~1.07 тэрбум хувилбар) ч гэсэн оноход нь
  ХҮҮХДИЙН ахицын өгөгдөл нээгддэг. Мөн "ийм код байхгүй" ба "код зөв ч
  сурагч биш" хоёрыг НЭГ ижил мессежээр буцаана — ялгаж хэлбэл код
  таамаглагчид "энэ код бодитой" гэсэн мэдээлэл алдана.
* ⚠ `GET /api/students` нь `toPublicUser`-ийг БИШ, нарийсгасан
  `toLinkedStudent` төсөөллийг буцаана: имэйл, урилгын код, төхөөрөмж,
  эрхийн талбарууд ОРОХГҮЙ. Насанд хүрэгчид хэрэгтэй нь "хүүхэд маань
  суралцаж байна уу" гэдэг л.
* Цэсний зүйлс `/admin`-тай ЯГ ИЖИЛ байрлалд гарна (өргөн дэлгэцийн
  хажуугийн багана + хэрэглэгчийн цэс), **доод туузанд ОРОХГҮЙ** — тэр тууз
  нь яг 5 зүйлд тохируулагдсан (`AppShell.tsx`-ийн `buildNav`).

**Хараахан байхгүй:** багшийн анги/бүлэг (бүлгийн код, бүлгээр нэгдэх),
өдрийн зорилтыг хүүхдийнхээ өмнөөс тохируулах, сурагч талаас "хэн намайг
харж байна вэ" гэдгийг харах/зөвшөөрөх дэлгэц.

## Суулгах

Node.js 20+ шаардлагатай.

```bash
npm install
cp .env.example .env.local     # утгуудыг бөглөнө
npm run db:push                # хүснэгтүүдийг үүсгэнэ
npm run db:seed                # 3 курс, 8 хичээл, 8 тэмдэг цутгана
npm run dev
```

> ⚠ **`db:push` нь схемд БАЙХГҮЙ хүснэгтийг устгах санал болгоно.**
> `DATABASE_URL`-ээ ЗААВАЛ хоосон, зөвхөн Tactiq-д зориулсан сан руу
> чиглүүлнэ үү. Өөр аппын сан руу заасан бол тэр аппын өгөгдөл алдагдана.

Тохиргоо зөв эсэхийг шалгах:

```bash
npm run db:check    # UTC бүс, utf8mb4, JSON round-trip, хүснэгтүүд
```

Дараа нь `/api/health` хаягаар Firebase-ийн түлхүүрүүд зөв уншигдсан эсэхийг
харна.

### Анхны админ

Системд бүртгүүлсэн **хамгийн эхний хэрэглэгч автоматаар `super`** эрх авна
(`/api/auth/register` дотор `app_config.has_admin` мөрийг түгжээтэйгээр
шалгаж, зөвхөн нэг удаа олгодог). Дараагийн сурагчид `user` эрхтэй, шууд
`active` төлөвтэй бүртгэгдэнэ — код сурах платформ дээр админы зөвшөөрөл
хүлээх нь утгагүй.

Эхний хэрэглэгч аль хэдийн үүссэн бол гараар эрх олгоно:

```bash
npm run grant:role -- email@example.com super
```

## Агуулга нэмэх

Хоёр зам байна:

1. **Хяналтын самбараас** — `/admin/courses` дээр курс үүсгээд, хичээл нэмж,
   дасгалуудыг нь бөглөнө. Хадгалахад сервер тал хариултын хэлбэрийг шалгаж,
   алдаатай бол тодорхой мессеж буцаана ("3-р дасгал: дор хаяж 2 сонголт
   хэрэгтэй").

2. **`scripts/seed.ts` дээр** — олон хичээлийг нэг дор бичихэд илүү хурдан.
   Скрипт нь идемпотент: `slug`-аар таньж шинэчилдэг тул олон удаа
   ажиллуулж болно. Сурагчийн явцад хүрэхгүй.

### Дасгалын дөрвөн төрөл

| Төрөл | Хариултын хэлбэр | Тайлбар |
| --- | --- | --- |
| `choice` | `{ index: 1 }` | Олон сонголтоос нэгийг |
| `fill` | `{ values: ["i"] }` | Кодын хоосон зайг нөхөх |
| `order` | `{ order: [2, 0, 1] }` | Мөрүүдийг зөв дараалалд |
| `output` | `{ text: "8" }` | Кодын үр дүнг бичих |

`output` ба `fill` дээр харьцуулалт нь том/жижиг үсэг, илүү зай, хашилтын
төрлийг үл харгалзана (`grade.ts` → `normalizeText`) — зөв бодсон хүүхэд
зөвхөн хэлбэрийн зөрүүнээс болж буруу авах ёсгүй.

## Тоглоомжуулалт

* **Оноо (XP)** → түвшин. Түвшинг санд хадгалдаггүй, `lib/tactiq/xp.ts` дээрх
  босгын хүснэгтээс тооцно — тэнцвэржүүлэлт өөрчлөхөд бүх мөрийг дахин
  бичих шаардлагагүй.
* **Зүрх** буруу хариулт бүрд хасагдаж, 30 минут тутам нэгээр сэргэнэ.
  Таймер хадгалдаггүй: `hearts` ба `hearts_updated_at` хоёроос уншилтын үед
  тооцно (cron шаардлагагүй, апп хаалттай байхад ч сэргэнэ). 0 зүрхтэй бол
  хичээл ЭХЛЭХ (`GET /lessons/[slug]`) БОЛОН дасгал ШАЛГАХ
  (`POST /exercises/[id]/check`) хоёулаа `403 no-hearts` буцаана —
  `currentHearts()` (`lib/api/lessons.ts`) хоёр газарт ижил дүрмийг хэрэгжүүлнэ.
* **Дараалал (streak)** нь `APP_TIMEZONE`-ийн өдрөөр тоологдоно. Хадгалагдсан
  утга хуучирсан байж болох тул харуулахдаа `displayStreak()`-аар шүүнэ.
* **Мөс (streak freeze)** — хэрэглэгч бүр 1-тэй эхэлнэ (`users.streakFreezes`).
  Бүтэн идэвхгүй өдөр тутамд НЭГ мөс хэрэглэгдэж дараалалыг тасдахаас
  хамгаална (2 өдөр алгассан бол 2 мөс хэрэгтэй). Хэрэглэгдэх мөч ба тоо
  ЗӨВХӨН `nextStreak()`-д (`lib/tactiq/day.ts`, хичээл дуусгахад) шийдэгддэг
  — зүрхтэй адил cron шаардлагагүй. Одоо мөсөөр хамгаалагдаж байгаа эсэхийг
  `isStreakProtectedByFreeze()` тооцож, толгой хэсэг болон "Зорилго" дэлгэц
  дээр дөлийн оронд цасан ширхэг (❄️) харуулна. Толгой хэсгийн дараалал
  дарахад `/streak` дэлгэц дээр Duolingo шиг САРЫН КАЛЕНДАРЬ нээгдэнэ —
  өдөр бүрийг 🔥 (хийсэн) / ❄️ (мөсөөр хамгаалсан) / ⚪ (алгассан) гэж
  ялгаж харуулна. Аль өдөр мөс зарцуулснаа түүхээрээ ЗӨВ харуулахын тулд
  `nextStreak()` мөс хэрэглэх МӨЧИД тухайн өдрүүдийг
  `daily_activity.frozen`-д тэмдэглэдэг (`markFrozenDays`,
  `.../complete/route.ts`) — дараа нь календарийг буцаад тооцоолоход
  ашиглана. Мөсийг ЭНД `STREAK_FREEZE_COST_GEMS` (`lib/streakFreeze.ts`,
  анхдагч 150) эрдэнээр худалдаж авч болно; `MAX_STREAK_FREEZES` (анхдагч
  2) нь зэрэг хадгалах дээд хязгаар. Гүйлгээ мөр түгжээтэйгээр
  (`FOR UPDATE`) баталгааждаг тул хоёр таб зэрэг дарсан ч эрдэнэ хоёр удаа
  хасагдахгүй.
* **Өдрийн зорилт** — нэг хичээл өдөрт ЗӨВХӨН НЭГ УДАА тоологдоно
  (`lesson_progress.last_completed_day`), эс бөгөөс нэг хичээлээ гурав дахин
  давтаад зорилтоо "биелүүлэх" боломжтой болно.
* **Амжилт** нь `metric >= threshold` гэсэн НЭГ л хэлбэртэй — админ талаас
  шинэ тэмдэг нэмэхэд код засах шаардлагагүй.
* **Үнэгүй туршилт.** Шинэ хэрэглэгч бүр бүртгүүлмэгц `TRIAL_DAYS`
  (`lib/billing.ts`, анхдагч **3 хоног**) Premium авна. Тусдаа `isTrial` туг
  БАЙХГҮЙ — туршилт нь ердийн `users.premiumUntil` дээр л суудаг тул
  "туршилт дуусгах" cron ч, тусдаа эрхийн салаа ч хэрэггүй: хугацаа
  өнгөрөхөд хэрэглэгч аяндаа ердийн хэрэглэгч болно, багц авбал ижил
  талбар сунгагдана.
* **Найз урих бонус.** Сурагч бүрийн профайл дээрх хувийн код нь ХОЁР
  зорилготой — эцэг эх холбогдоход, эсвэл шинэ найз урихад. "Найздаа
  холбоос илгээх" товч `/register?ref=CODE` хэлбэрийн БҮТЭН холбоос
  хуулна — найз дарахад кодыг гараар бичихгүйгээр талбар өөрөө бөглөгдөнө
  (`AuthCard.tsx`). Тохирсон кодоор бүртгүүлбэл **ХОЁУЛАА**
  `REFERRAL_BONUS_DAYS` (анхдагч **3 хоног**) үнэгүй Premium авна —
  үлдсэн хугацаан ДЭЭР нэмэгдэнэ (`extendPremium()`, `lib/api/premium.ts`).

  **Хоног нь бүртгэлийн мөчид ОЛГОГДОХГҮЙ.** Бүртгэл нь зөвхөн
  `users.referredBy` болон `referrals` мөрийг тэмдэглэнэ; хоног нь хоёр
  нөхцөл ХАМТДАА биелэхэд олгогдоно (`lib/api/referralReward.ts`):

  1. урьгдсан талын **имэйл баталгаажсан** (`email_verified` claim), БА
  2. урьгдсан тал **хичээл дуусгасан**
     (`POST /api/learn/lessons/[lessonId]/complete`).

  Энэ нь farming-ийн эсрэг: бүртгэл нь үнэгүй бөгөөд хязгааргүй давтагдах
  үйлдэл, харин имэйл баталгаажуулах + хичээл дуусгах нь тийм биш.
  Шалгалт хичээл дуусгах БҮРД явдаг тул имэйлээ хожим баталгаажуулсан хүн
  дараагийн хичээл дээрээ урамшуулалдаа хүрнэ.

  **Лимит нь УРИХ ТООНД БИШ, ХОНОГТ.** Найзаа ХЯЗГААРГҮЙ урьж болно —
  `api/auth/register` дээр ямар ч тоолол байхгүй, урилга бүр `referrals`
  хүснэгтэд бүртгэгдэнэ. Зөвхөн УРЬСАН талд нэмэгдэх хоног таглагдана:
  `REFERRAL_REWARD_MAX_FRIENDS` (**15**) найзаас = дээд тал нь 45 хоног.
  Урьгдсан ШИНЭ хэрэглэгч өөрийн 3 хоногоо ямар ч тохиолдолд авна — тэр
  хүн лимит дүүрснийг мэдэх аргагүй.

  > ⚠ Тогтмолын нэрийг `REFERRAL_MAX_FRIENDS`-ээс СОЛЬСОН: хуучин нэр нь
  > "дээд тал нь 15 найз урьж болно" гэж уншигдаж, UI-д ч яг тэр утгаар
  > бичигдсэн байв ("Дээд тал нь 15 найз"). Логик нь ХЭЗЭЭ Ч тийм байгаагүй. Лимит нь
  ОЛГОГДСОН (`referrals.rewarded_at` тавигдсан) мөрүүдээр тоологдоно;
  тооллын үед урьсан талын мөрийг `FOR UPDATE`-ээр түгжинэ, эс бөгөөс хоёр
  найз яг зэрэг дуусгахад лимит давна.

  Давхардлаас `referrals_referee_uq` индекс болон `users.referralRewardedAt`
  (нөхцөлт `IS NULL` UPDATE-ээр нэхэмжлэгддэг) хамгаална. Буруу/хоосон код

  > баталгаажаагүй хэрэглэгчид сануулга харуулж, "Баталгаажууллаа" товчоор
  > `reload()` + `getIdToken(true)` хийнэ — ХОЁУЛАА заавал, эс бөгөөс
  > токен доторх claim нэг цаг хүртэл хуучин хэвээр үлдэж сервер
  > "баталгаажаагүй" гэж үзсээр байна. ⚠ Баталгаажуулалт нь апп-ын
  > хандалтыг ХААХГҮЙ — зөвхөн урамшууллыг хойшлуулна.
* **Амжилтын тэмдэг** (`/achievements`) — Duolingo маягийн ОЛОН ШАТТАЙ

  > оруулбал аль хэдийн авсан шат БУУРЧ харагдана (3 найзтай хүн "2-р

  > (нэг газарт бичигдээд нөгөө нь мартагдвал "нээгдсэн" тэмдэг хоосон
  > явцтай харагдана), тооцоолсон утга хэзээ ч зөрөхгүй.

  > бүтэн дэлгэц эзэлж, гүйлгэхгүйгээр харьцуулах боломжгүй байв. Явцын
  > зураасыг ч авсан: зураас нь ДАРААГИЙН шат хүртэлх хувь бөгөөд тэр нь
  > шат бүрд тэгээс эхэлдэг тул тэмдэг хооронд харьцуулах утгагүй. Оронд
  > нь шатны тоо ("3 / 8") — энэ нь тэмдэг даяар нэг утгатай.

  > гаргах цорын ганц зам нь мөрийн `updated_at` зэргээс таамаглах бөгөөд
  > тэр нь ХУДАЛ огноо хэвлэнэ.
  >
  > ⚠ Явцыг ӨМНӨХ шатнаас нь эхлүүлж хэмжинэ, тэгээс биш: 30 → 50 өдрийн
  > шатанд 31 өдөртэй хүн 62% (31/50) БИШ, 5% (1/20) байх ёстой — эс бөгөөс
  > шинэ шат эхлэх бүрд зураас бараг дүүрэн харагдаж ахиц мэдрэгдэхгүй.

  > ⚠ ТУСДАА ХҮСНЭГТ БАЙХГҮЙ. "Бүх хичээл дуусгасан уу" гэдгийг

  > зөрөх боломжтой — курст ШИНЭ хичээл нэмэгдвэл хуучин "дууссан" мөр худал

  > ⚠ `total > 0` шалгалт ЗААВАЛ. Хичээлгүй курст `completed` ба `total`

  > олгогдсоныг гадныханд хэлж, өөр хүнийхийг таамаглах боломж нээнэ.

  >
  > ⚠ ЖАГСААЛТ нь Premium эрхгүй хүнд ч бүрэн харагдана, зөвхөн ХЭВЛЭХ нь
  > хаалттай. Дуусгасан курсаа нуувал хийсэн хөдөлмөрийг нь нуух бөгөөд юу
  > авахаа мэдэхгүй хүн Premium авахгүй.
  >
  > ⚠ Хэвлэхэд аппын хүрээ `print:hidden`-ээр нуугдана. `printOnly()` нь
  > бусад гэрчилгээг түр нуудаг — `window.print()` нь БҮХ хуудсыг хэвлэдэг
  > тул үүнгүй бол гурван гэрчилгээтэй хүн гурван хуудас гаргана.

  > 50KB+ жин нэмнэ.

  > тараахаас сэргийлнэ.
  >

  > байгаа нь ФАЙЛ дэмжинэ гэсэн үг БИШ. Дэмжихгүй бол зургийг ТАТАЖ өгөөд

  > ⚠ **САР ӨНЖВӨЛ НЭГ ШАТ БУУНА** (`IDLE_WEEKS_TO_DEMOTE = 4`,
  > `applyIdleDecay()`). Эс бөгөөс нэг удаа Болор лигт хүрсэн хүн хэзээ ч
  > буцаж буухгүй бөгөөд дээд лиг идэвхгүй данснуудаар дүүрнэ. Тооцоо нь
  > `course_leagues.last_week_key` дээр суурилах ба **идемпотент**:
  > шат бууруулах бүрд тэмдэглэгээг 4 долоо хоногоор УРАГШЛУУЛНА, тиймээс
  > нэг өдөрт хэдэн ч удаа дуудсан ижил үр дүн гарна. Тэмдэглэгээг
  > "одоо" болгож тавьбал хагас жил ирээгүй хүн ганцхан шат буух байсан;
  > урагшлуулснаар алгассан САР БҮРД нэг шат буурна.
  >
  > ⚠ `daysBetween(a, b)` нь **`a - b`** (`lib/tactiq/day.ts`).
  > `daysBetween(weekKey, marker)` гэж бичих ёстой — эсрэгээр бичвэл
  > үргэлж сөрөг гарч, бууралт ХЭЗЭЭ Ч ажиллахгүй (энэ алдаа нэг удаа
  > гарсан, туршилтаар баригдсан).

  > ⚠ **CRON БАЙХГҮЙ, ДҮГНЭЛТ ЗАЛХУУ.** Долоо хоног солигдоход бүх
  > хэрэглэгчийг нэг дор дүгнэх ажил ажиллуулах газаргүй — PM2 нь cluster
  > горимд олон instance-аар явдаг тул нэг cron бүх instance дээр давхар
  > гүйнэ. Оронд нь хэрэглэгч эргэж ирэхэд (`GET /api/league`, эсвэл хичээл
  > дуусгахад) **өөрийнх нь** өмнөх долоо хоног дүгнэгдэнэ. Энэ нь зөвхөн
  > ЭНЭ ШАЛТГААНААР зөв: долоо хоног дуусмагц тэр бүлгийн XP-үүд ХӨЛДӨНӨ
  > (`league_members` мөр нь долоо хоног тус бүрд тусад нь) — тиймээс хэн
  > хэдэн сарын дараа орж ирсэн ч ЯГ ижил байр гарна. Давхар дэвшилтээс
  > `settled_at IS NULL` нөхцөлт UPDATE хамгаална.
* **Найзууд** (`/friends`) — сурагчийн хувийн кодоор хүсэлт илгээж,
  зөвшөөрөгдвөл найз болно. Нэр/имэйлээр **ХАЙХ БОЛОМЖ ЗОРИУДААР БАЙХГҮЙ**:
  хүүхдийн платформ дээр танихгүй хүн жагсаалтаас хүүхэд сонгож чаддаг байх
  нь эрсдэл — код мэддэг хүн л хүсэлт илгээнэ. Хосыг **эрэмбэлж** хадгална
  (`user_a_uid < user_b_uid`) тул А→Б, Б→А гэсэн давхар мөр үүсэхгүй; хэн
  санаачилсныг `requested_by` тусад нь хадгална. Татгалзсан хүсэлтийн мөрийг
  УСТГАНА ("declined" гэж хадгалбал тэр хүн дахин хүсэлт илгээж чадахгүй
  болно).
* **Хамтын даалгавар** (`friend_quests`) — хоёр найз долоо хоногт **300 XP**
  цуглуулбал хоёулаа **30 зоос** авна. Хувь нэмэр тусад нь бичигдэж
  НИЙЛБЭРЭЭР дүгнэгдэнэ, тиймээс нэг нь нөгөөгөө нөхөж чадна. Нэг хүн долоо
  хоногт ЗӨВХӨН НЭГ даалгавартай — эс бөгөөс нэг хичээлийн XP олон даалгаварт
  давхар тоологдож шагнал үржинэ. Шагналыг `rewarded_at IS NULL` нөхцөлт
  UPDATE-ээр НЭГ УДАА нэхэмжилнэ (`completed_at` ганцаараа хангалтгүй:
  дууссаны дараах хичээл бүр ч тавигдсан утгыг буцаана).
* **Elo үнэлгээ** (`users.rating`, анхдагч 1200) — шатар/даамын тоглолтын үр
  дүнгээр өсдөг, буурдаг тоо (`lib/tactiq/rating.ts`). Ялалтын ТООНООС
  ялгаатай нь ӨРСӨЛДӨГЧИЙН ХҮЧИЙГ тооцно: сул ботыг 100 удаа ялсан хүн
  хүчтэй тоглогчийг нэг ялсан хүнээс дээгүүр гарахгүй. Ботын хүчийг
  түвшнээр нь тогтоов (эхлэгч 800 / дунд 1200 / ахисан 1600). K коэффициент
  эхний 20 тоглолтод 40, дараа нь 20 (2000+ дээр 10) — шинэ тоглогчийн
  үнэлгээ хурдан жинхэнэ түвшиндээ ойртоно.

  > ⚠ Хүн-хүний тоглолтод ХОЁУЛАНГ нь **нэг гүйлгээнд, ижил "өмнөх" утгаар**
  > бодно (`applyHumanGame`). Эхлээд нэгийг нь бичээд дараа нь нөгөөг нь
  > шинэ утгаар бодвол Elo-гийн тэг нийлбэрийн шинж эвдэрч, системд оноо
  > чимээгүй үүсэх/алга болно. Мөрүүдийг цагаан толгойн дарааллаар түгжсэн
  > нь deadlock-оос хамгаална.
  >
  > ⚠ Лиг ба Elo нь ХОЁР ӨӨР ойлголт: лиг нь долоо хоногийн ХИЧЭЭЛИЙН
  > идэвхийг, Elo нь ТОГЛОЛТЫН хүчийг хэмжинэ. Хичээлдээ шамдуу хүүхэд
  > тоглоомдоо сул байж болно — нэг тоо болгож хольвол аль аль нь утгаа
  > алдана.
* **Курст зарцуулсан цаг** (`course_time`) — курс тус бүрийн нийт хугацаа,
  `/courses` дээр харагдана. `lesson_progress`-д хадгалж БОЛОХГҮЙ: тэр
  хүснэгт хичээл бүрд зөвхөн НЭГ мөртэй тул давтан үзсэн хугацаа хаягдана.

  > ⚠ Хугацааг КЛИЕНТ хэмждэг тул ИТГЭЛТЭЙ БИШ (таб ард нээлттэй хэвтвэл
  > цаг тоологдсоор байна). Сервер нэг хичээлээс дээд тал нь 2 цаг хүлээн
  > авна, мөн энэ тоо нь ЗӨВХӨН статистик — оноо, эрх, шагнал ХЭЗЭЭ Ч
  > үүнээс хамаарахгүй.
* **Premium гишүүнчлэл** (`/premium`) — таван багц:

  | Багц | Үнэ | Хугацаа | Хүн | Нэг хүнд/сар |
  |---|---|---|---|---|
  | Сарын | 9,900₮ | 30 хоног | 1 | 9,900₮ |
  | 3 сарын | 26,900₮ | 90 хоног | 1 | ~8,967₮ |
  | 6 сарын | 49,900₮ | 180 хоног | 1 | ~8,317₮ |
  | Жилийн | 89,000₮ | 365 хоног | 1 | ~7,417₮ |
  | **Гэр бүлийн** | 159,000₮ | 365 хоног | **5** | **~2,650₮** |

  > ⚠ Гэр бүлийн багцыг `monthlyEquivalent()`-ээр харьцуулж БОЛОХГҮЙ:
  > 159,000 / 12 = 13,250₮ нь жилийн багцын 7,417₮-с үнэтэй харагдана.
  > Зөв зүйрлэл нь `perSeatMonthly()` — суудлын тоонд хуваасны дараах утга.
  > `savingsPercent()` мөн суудлыг тооцдог (эс бөгөөс хэмнэлт ХАСАХ гарна).

  Худалдаж авбал
  `users.premiumUntil` сунгагдаж, зүрх ХЭЗЭЭ Ч дуусахгүй болно
  (`isPremiumUser()`, `lib/tactiq/xp.ts`). Багцын үнэ, хоног, хэмнэлтийн
  тооцоо БҮГД `lib/billing.ts`-д — сервер төлөх дүнг эндээс л уншина,
  клиентээс ХЭЗЭЭ Ч авахгүй. Сунгалт нь үлдсэн хоног ДЭЭР нэмэгддэг тул
  туршилтын хугацаа шатахгүй.

  **Гэр бүлийн багц** нь 5 хүнийг хамарна — худалдан авагч + холбогдсон
  4 хүүхэд (`FAMILY_SEATS`, `lib/api/family.ts`).

  > ⚠ Суудал нь ТУСДАА "гэр бүлийн код" БИШ, байгаа эцэг эх ↔ сурагчийн
  > холбоосоор (`student_links`, зөвхөн `relation = "parent"`) олгогдоно.
  > Хоёр дахь нэгдэх механизм зохиовол хэрэглэгч шинэ ойлголт сурах ба
  > ижил зүйл хоёр газар зөрүүтэй хадгалагдана.
  >
  > ⚠ Худалдан авагч ӨӨРӨӨ нэг суудал эзэлнэ — гишүүдэд 4 суудал.
  >
  > ⚠ `FAMILY_SEATS`-ыг БУУРУУЛЖ болохгүй. Олгогдсон суудлууд
  > `family_seats`-д мөрөөр үлддэг тул хязгаарыг багасгавал одоо байгаа
  > гэр бүлүүд хязгаараасаа хэтэрсэн төлөвт орно. Нэмэх нь аюулгүй.
  >
  > ⚠ `family_seats` хүснэгт ЗААВАЛ хэрэгтэй, `student_links`-ээр тоолж
  > болохгүй: холбоосыг САЛГАЖ болдог. Салгасныг суудал сулласан гэж үзвэл
  > эцэг эх 4 хүүхэд холбоод, эрх ороод, салгаад, өөр 4-ийг холбож — нэг
  > багцаар ХЯЗГААРГҮЙ хүнд эрх тарааж чадна. Олгосон эрхийг буцааж авах
  > боломжгүй тул суудал нь ОЛГОСОН мөчид түгжигдэнэ; зөвхөн багцын
  > хугацаа дуусахад сулрана (цэвэрлэх cron ХЭРЭГГҮЙ).
  >
  > ⚠ Суудал ХОЁР цэгээс олгогдоно: (1) төлбөр батлагдахад
  > (`markPaid()` → `grantFamilySeats()`), (2) багц авсны ДАРАА хүүхэд
  > холбоход (`linkStudentByCode()` → `grantSeatOnLink()`). Хоёрдугаарыг
  > орхивол "төлчихөөд дараа нь хүүхдээ нэмсэн" эцэг эх юу ч авахгүй
  > бөгөөд шалтгааныг нь олох боломжгүй.
  >
  > ⚠ `grantPremiumUntil()` нь хоног НЭМЭХГҮЙ, ОГНОО тавина — идемпотент.
  > Хоног нэмдэг байсан бол салгаад дахин холбох бүрд жил нэмэгдэнэ.
  > `GREATEST` нь хүүхдийн ӨӨРИЙН урт эрхийг хамгаална — гэр бүлд нэгдэх
  > нь хэний ч эрхийг ХЭЗЭЭ Ч богиносгохгүй.
  >
  > ⚠ Зөвхөн `relation = "parent"`. Багш нар сурагчидтайгаа ижил
  > хүснэгтээр холбогддог тул шүүхгүй бол гэр бүлийн багц ангийн хямдрал
  > болж хувирна.

  Төлбөрийг
  [QPay](https://qpay.mn)-ээр (Монголын бүх банкны аппаар уншигдах нэг QR)
  хийнэ:
  * `QPAY_CLIENT_ID`/`SECRET`/`INVOICE_CODE` тохируулаагүй үед **sandbox
    горим** идэвхжинэ (`lib/api/qpay.ts`) — хуурамч QR буцааж, урсгалыг
    бүтнээр нь (checkout → QR → "төлөгдсөн") локал турших боломжтой.
    `/api/billing/subscriptions/[id]/dev-complete` нь ЗӨВХӨН энэ горимд
    ажиллана, жинхэнэ QPay холбогдмогц автоматаар 403 болно.
  * Жинхэнэ горимд клиент секунд тутам захиалгын явцыг poll хийж
    (`GET /api/billing/subscriptions/[id]`) шалгана — локал хөгжүүлэлт дээр
    QPay-ийн webhook `localhost`-руу хүрэхгүй тул энэ poll л найдвартай.
    Продакшн дээр webhook (`/api/billing/webhook/qpay`) НЭМЭЛТ хурдтай зам
    болдог ч хоёул ирж болно — `markSubscriptionPaid()` идэмпотент (мөр
    түгжээтэйгээр дахин шалгадаг тул давхар сунгахгүй).

## Одоогоор хийгдээгүй зүйлс

* **Python ажиллуулах.** Кодын засварлагч дээр JavaScript нь Web Worker дотор
  жинхэнээр ажиллана (timeout, DOM-гүй тусгаарлалттай), HTML нь sandbox
  iframe дээр урьдчилан харагдана. Python-ыг ажиллуулахын тулд Pyodide
  (~10MB WASM) татах эсвэл сервер талд sandbox барих шаардлагатай — аль нь ч
  ороогүй. Python төсөл дээр "Ажиллуулах" дарвал үүнийг ИЛ хэлнэ, хуурамч
  үр дүн үзүүлэхгүй.
* **Push мэдэгдэл.** Тохиргоон дахь "Мэдэгдэл" унтраалга нь одоогоор зөвхөн
  ХҮСЭЛТИЙГ хадгална. Сануулга илгээх механизм (FCM эсвэл имэйл) нэмэгдээгүй.
* **Англи хэл.** `language` талбар хадгалагдаж байгаа ч UI бүхэлдээ монгол —
  орчуулгын давхарга ороогүй.
* **Профайл зураг байршуулах.** `photo_url` талбар ба Firebase Storage
  тохиргоо бэлэн, харин байршуулах UI нэмэгдээгүй.
