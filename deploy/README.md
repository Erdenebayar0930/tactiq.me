# Байршуулалт

Энэ хавтас нь Ubuntu/Debian сервер дээр Tactiq-г ажиллуулах **загвар
скриптүүд** агуулна. Тодорхой хостинг (домэйн, хэрэглэгчийн нэр, нууц үг)
руу заасан утга ЭНД БАЙХГҮЙ — скрипт бүрийн эхэнд байгаа хувьсагчдыг өөрийн
серверийн утгаар солино.

> Өмнө нь энд өөр төслийн (ББУЧ / `dash.bbuchmongol.com`) бодит серверийн
> алхам алхмаар заавар байсан. Tactiq-д хамаагүй, буруу сервер рүү
> байршуулах эрсдэлтэй тул хассан. Скриптүүд нь дахин ашиглагдах хэвээр.

## Файлууд

| Файл | Зориулалт |
| --- | --- |
| `setup-server.sh` | Шинэ сервер бэлдэх — Node, PostgreSQL, Redis, nginx, PM2, эхний clone |
| `deploy.sh` | Шинэ хувилбар гаргах — pull, install, build, PM2 reload |
| `ecosystem.config.js` | PM2-ийн процессын тохиргоо (cluster mode) |
| `nginx/tactiq.conf` | Урвуу прокси, статик файлын кэш |
| `backup.sh` | Нөөцлөлт — сан + эх код, хугацаатай цэвэрлэгээтэй |

## Эхний удаа

```bash
# Серверт root эрхээр
git clone https://github.com/Erdenebayar0930/tactiq.me.git /var/www/tactiq
cd /var/www/tactiq

# Скриптийн дээд талын хувьсагчдыг ЭХЛЭЭД засна (домэйн, DB нэр/нууц үг)
nano deploy/setup-server.sh

sudo bash deploy/setup-server.sh
```

Дараа нь орчны хувьсагчдыг бөглөнө:

```bash
cp .env.example .env.local
nano .env.local        # DATABASE_URL, FIREBASE_*, NEXT_PUBLIC_*, QPAY_*

# ⚠ Нууц файлыг хамгаална — зөвхөн root уншина.
chown root:root .env.local && chmod 600 .env.local
```

> **⛔ Үйлдвэрлэлийн нууц утга ЗӨВХӨН ЭНД байна.** QPay-ийн мерчантын нууц,
> сангийн нууц үг, Firebase Admin-ий түлхүүрийг хөгжүүлэгчийн компьютер
> дээр буулгаж хадгалахгүй — дискэн дээрх файл нь нөөцлөгдөж, синк хийгдэж,
> хавтас хуваалцахад дагалддаг. Нэг ч удаа ил гарвал нууц үгээ СОЛИХООС
> өөр сэргээх арга байхгүй.
>
> Локал `.env.local` дотор зөвхөн **sandbox** QPay, локал Postgres байна —
> ингэснээр `npm run dev` жинхэнэ нэхэмжлэл үүсгэх боломжгүй.
>
> `deploy.sh` нь deploy бүрд зөвшөөрлийг шалгаж, 600 биш бол засна.

Схемийг үүсгээд агуулга цутгана:

```bash
npm run db:push        # схем үүсгэнэ (устгах санал гарвал уншаад баталгаажуулна)

# Агуулга цутгах — курс тус бүр ТУСДАА скрипттэй (`npm run` гэж бичээд
# бүх seed:* жагсаалтыг харж болно). Хэрэгтэйг нь сонгоно:
npm run seed:piano
npm run seed:puzzles
npm run seed:networks
npm run seed:kids
npm run seed:draughts
npm run seed:go
npm run seed:coding

npm run build
pm2 start deploy/ecosystem.config.js
pm2 save
```

## Шинэ хувилбар гаргах

```bash
cd /var/www/tactiq && sudo bash deploy/deploy.sh
```

`pm2 reload` (`restart` БИШ) ашигладаг тул cluster mode-ийн worker бүрийг
дараалан сольж, доголдолгүй (zero-downtime) шинэчилдэг.

## Олон хэрэглэгч зэрэг хандахад (cluster mode + Redis)

`ecosystem.config.js` анхдагчаар `exec_mode: "cluster"`, `instances: 2` —
Node.js нэг цөмд нэг процессоор ажилладаг тул fork mode (`instances: 1`) нь
CPU-гоор хурдан хязгаартаа хүрдэг. Cluster mode нь ижил 3000 портыг хэд
хэдэн CPU цөм дээр зэрэг сонсуулна (Nginx тохиргоо өөрчлөгдөхгүй).

**Тохируулах алхмууд:**

1. `nproc`-оор боломжит цөмийн тоог шалгаад `ecosystem.config.js`-ийн
   `instances`-ыг тохируулна (MySQL/Redis/Nginx-д нэг цөм үлдээхийг
   зөвлөнө — жишээ нь 4 vCPU дээр `instances: 3`).
2. `.env.local`-д `REDIS_URL=redis://127.0.0.1:6379` тохируулна (`setup-server.sh`
   Redis-ийг автоматаар суулгадаг). **Cluster mode-д ЗААВАЛ шаардлагатай** —
   Redis-гүй бол хурдны хязгаарлагч (`rateLimit.ts`), курсын каталогийн кэш
   (`cache.ts`) instance тус бүрдээ тусдаа ажиллаж, зөв ажиллахгүй.
3. `DATABASE_POOL_MAX`-ыг instance-ийн тоогоор үржүүлж MySQL-ийн
   `max_connections`-той харьцуулна (`.env.example`-ийн тайлбар харна уу).

**Юу засагдсан бэ (энэ тохиргоог нэмэхээс өмнө олдсон бодит алдаанууд):**

* `isOverloadError` (`src/lib/api/auth.ts`) нь Drizzle-ийн боосон алдааны
  `.cause`-ыг шалгадаггүй байсан тул сан завгүй үед 503 биш 500 буцдаг байв
  — 200 зэрэг хүсэлтээр шалгахад 89/200 нь 500 болж, клиент "апп эвдэрсэн"
  гэж ойлгож, дахин оролддоггүй байсан. Одоо `.cause` гинжийг шалгаж 503-руу
  зөв хөрвүүлдэг.
* `/api/courses` нь хэрэглэгч бүрд ХИЧЭЭЛ БҮРИЙН LEFT JOIN + GROUP BY
  ажиллуулдаг байсан — олон зуун сурагч зэрэг ачаалахад (жишээ нь хичээл
  эхлэх үе) сан хурдан дараалалдаа орно. Одоо хэрэглэгчээс хамаарахгүй
  каталогийг 30 секунд кэшлэж, хэрэглэгч тус бүрт зөвхөн жижиг, индекслэгдсэн
  явцын асуулга л ажилладаг.
* `proxy_buffering off` (nginx) — nginx хариуг клиент рүү шууд дуслуулдаг
  тул УДААН СҮЛЖЭЭТЭЙ хэрэглэгч бүр Node-ийн холболтыг татаж дуустал барьдаг
  байв. Хэдэн зуун гар утас 3G дээр байхад л апп "унасан" мэт болно. Одоо
  `proxy_buffering on` — nginx хариуг өөртөө аваад Node-ыг шууд суллана.
* Postgres pool-д `statement_timeout` байхгүй байсан — нэг гацсан асуулга
  холболтыг мөнхөд барьж, ҮЛДСЭН БҮХ хүсэлт цуг унадаг. Одоо 10 секундээр
  таслах тул гэмтэл тухайн route-д хязгаарлагдана.
* API хүсэлт БҮР `users` хүснэгтээс дуудагчийн мөрийг уншдаг байсан —
  polling дэлгэц (`/play` дараалал) энэ ачааллыг хэрэглэгчийн тоогоор
  үржүүлнэ. Одоо ЗӨВХӨН УНШИХ хүсэлтэд 3 секунд кэшилнэ; бичих үйлдэл
  (зүрх, XP) ҮРГЭЛЖ шинэ мөр авдаг тул өгөгдөл гажихгүй.
* `/api/play/online` нь лоббид сууж буй хэрэглэгч бүрийн polling-д хоёр
  `COUNT(*)` ажиллуулдаг байсан. Хувийн өгөгдөл огт агуулаагүй тул одоо
  5 секунд хуваалцсан кэшэд — Postgres руу очих тоо хэрэглэгчийн тооноос
  хамаарахгүй болов.
* `setup-server.sh` нь MariaDB суулгадаг байсан — Tactiq нь PostgreSQL
  хэрэглэдэг (`pg` драйвер, `drizzle.config.ts` → `dialect: "postgresql"`,
  `schema.ts` → `pg-core`) тул ажиллуулсан сервер дээр апп сан руугаа огт
  холбогдохгүй байсан. PostgreSQL + Redis суулгахаар засав; хуучин сервер
  дээр `sudo apt-get purge mariadb-server` хийж болно.

## Анхаарах зүйлс

**`NEXT_PUBLIC_*` нь build үед шигтгэгддэг.** Тэдгээрийг өөрчилсний дараа
`pm2 restart` хангалтгүй — ЗААВАЛ `npm run build` дахин ажиллуулна.

**`db:push` нь схемд байхгүй хүснэгтийг устгах санал болгоно.** Tactiq-д
зориулсан ТУСДАА сан ашиглана уу. Нэг санг өөр апптай хуваалцах шаардлагатай
бол `drizzle.config.ts` дэх `tablesFilter`-т тэр аппын угтварыг нэмнэ.

**Байршуулсны дараа шалгах:**

```bash
curl https://<домэйн>/api/health
```

`postgres: "ok"`, `firebaseClient: "configured"` гэсэн хариу ирэх ёстой.
`firebaseClient: "missing"` бол `NEXT_PUBLIC_FIREBASE_*` тохируулаагүй эсвэл
тохируулсны дараа дахин build хийгээгүй байна.

**Эхний админ.** Системд бүртгүүлсэн хамгийн эхний хэрэглэгч автоматаар
супер админ болно. Хэрэв аль хэдийн хэрэглэгч үүссэн бол:

```bash
npm run grant:role -- email@example.com super
```

## НӨӨЦЛӨЛТ

```bash
bash deploy/backup.sh
```

Гаргах зүйл: `../backups/daamal-<огноо-цаг>/` дотор
`db-tactiq.sql` (бүх схем), `code-*.tar.gz`, `README.md`.

### Тохиргоо

| Хувьсагч | Анхдагч | Юу вэ |
| --- | --- | --- |
| `BACKUP_KEEP_DAYS` | `14` | Үүнээс хуучин нөөцлөлт **устана** |
| `BACKUP_DIR` | `../backups` | Хаана хадгалах вэ (⚠ репогийн ГАДНА) |
| `BACKUP_CODE` | `1` | `0` бол зөвхөн сан — серверт код нь git-д байдаг |
| `PG_DUMP` | `pg_dump` | Windows дээр бүтэн замыг өгнө |

⚠ **Хуучин нөөцлөлтийг зөвхөн ШИНЭЭ АМЖИЛТТАЙ болсны дараа
цэвэрлэнэ.** Эсрэгээр бол сан унтарсан өдөр шинэ нөөцлөлт
бүтэлгүйтээд, хуучин нь цэвэрлэгдэж гартаа юу ч үлдэхгүй болно.

⚠ **Нууц утга ОРОХГҮЙ** (`.env*.local`). ⚠ Dump дотор
хэрэглэгчдийн **хувийн мэдээлэл** байна.

### Хуваарь — сервер (cron)

Өдөр бүр шөнө 03:30-д, 30 хоног хадгална:

```bash
sudo crontab -e
```

```cron
30 3 * * * BACKUP_KEEP_DAYS=30 BACKUP_CODE=0 bash /var/www/tactiq/deploy/backup.sh >> /var/log/tactiq/backup.log 2>&1
```

⚠ `BACKUP_CODE=0` — серверт код нь GitHub дээр байдаг тул дахин
архивлах шаардлагагүй. Сан нь орлох боломжгүй хэсэг.

⚠ **НӨӨЦЛӨЛТ НЭГ МАШИНД БАЙХ НЬ НӨӨЦЛӨЛТ БИШ.** Диск унавал
хоёулан зэрэг алга болно. Үүлэн сан руу хуулах алхамыг нэмнэ.

### Хуваарь — Windows (локал)

```powershell
$cmd = 'C:\Program Files\Git\bin\bash.exe'
$args = '-lc "PG_DUMP=/c/Program\ Files/PostgreSQL/18/bin/pg_dump.exe BACKUP_KEEP_DAYS=14 bash /d/Coderoot/tactiq.me/deploy/backup.sh"'
schtasks /Create /TN "Daamal backup" /TR "`"$cmd`" $args" /SC DAILY /ST 03:30
```

Устгах: `schtasks /Delete /TN "Daamal backup" /F`
