# Daamal.org — Чансааны (Rating) системийн зохиомж

Энэ баримт нь шатар, даамын **тоглолтын хүчийг** хэмжих системийн бүрэн
тодорхойлолт. Хэрэгжүүлэхэд шаардлагатай томьёо, тогтмол, сангийн бүтэц,
API, pseudocode, бодит тоон жишээ бүгд энд байна.

> **Хэрэгжүүлэхээс өмнө уншина уу:** §0 нь одоогийн код, сантай ямар
> зөрчил байгааг, ямар шийдвэр гаргах шаардлагатайг нэрлэнэ. Тэр
> шийдвэрүүд хийгдээгүй бол §1-ээс хойшхийг хэрэгжүүлэх нь хагас систем
> үүсгэнэ.

## ШИЙДВЭР (2026-09-17) — ЧАНСАА ЗӨВХӨН ЧАНСАА ТОГТООХ ТЭМЦЭЭНЭЭР

Эзний шийдвэр: **чансаа зөвхөн «чансаа тогтоох» тэмцээнээр өрнөнө.**
Энэ нь доорх бүх хэсгийг дарж давамгайлна.

- **Ердийн онлайн тоглолт** (тоглогч хайх, найзаа урих) — **чансаагүй**.
  `api/play/rooms/[roomId]/end` нь зөвхөн ялалт/хожигдол/тэнцээний
  статистик бичнэ. Шалтгаан: хосыг тоглогч өөрөө сонгодог тул хоёр хүн
  тохиролцоод оноо шилжүүлэх боломжтой.
- **Ботын дадлага** — **чансаагүй**. `users.rating` нь ТУСДАА зүйл
  (дадлагын «үнэлгээ», профайл дээр ингэж бичигдэнэ), `player_ratings`
  нь чансаа. `rateGame` нь `users.rating`-д ХҮРЭХГҮЙ.
- **Тэмцээн** нь `rated` тугтай байх ёстой (`tournament_series.rated` →
  `tournaments.rated` → tactiq `RemoteTournament.rated`). Анхдагч нь
  `false`: хөгжөөнт тэмцээнд оролцоод чансаа унагана гэвэл шинэ сурагч
  тэмцээнээс эмээнэ. Жагсаалт дээр «Чансаа тогтоох» шошго ИЛ гарна.
- **Хожигдол оноо ХАСНА** (тэг нийлбэр). Хил: `POST /api/tournament/game`
  — `tournamentId` заавал, `rated !== true` бол `{ status: "unrated" }`.

## 0. ОДООГИЙН БАЙДАЛ ба ШААРДЛАГАТАЙ ШИЙДВЭР

Код дээр аль хэдийн байгаа зүйлс:

| Юу | Хаана | Одоогийн байдал |
| --- | --- | --- |
| Elo тооцоо | `src/lib/tactiq/rating.ts` | Ажиллаж байна, гэхдээ **нэг** rating |
| Тоглолтын бичилт | `src/lib/api/rating.ts` | `applyBotGame`, `applyHumanGame` |
| Хадгалалт | `users.rating`, `users.ratingGames` | **Нэг багана**, анхдагч **1200** |
| Ялалт/хожигдол | `users.chessWins`, `users.draughtsWins`… | Тоглоомоор **аль хэдийн** салсан |
| Лиг | `src/lib/tactiq/league.ts` | **Долоо хоногийн XP**-ээр, rating-тай холбоогүй |
| Тэмцээний хэлбэр | `src/lib/tactiq/tournamentFormat.ts` | arena / swiss / knockout / team |
| Хурд | тэндээ, `speedFromTimeControl` | bullet / blitz / rapid / classical (**цагийн хяналтаас тооцогдоно**) |

### 0.1 Зөрчил №1 — анхны утга 1200 ≠ 1500

Одоо `DEFAULT_RATING = 1200`. Шаардлага нь **1500**.

**Санал:** бүх байгаа rating-т `+300` нэмж шилжүүлнэ, `ratingGames`-ыг
хөндөхгүй. Тэглэхгүй шалтгаан: тоглосон хүмүүсийн харьцангуй зөрүү нь
бодит мэдээлэл; тэглэвэл тэднийг дахин 10 тоглолт placement-д оруулна.

```sql
UPDATE users SET rating = rating + 300 WHERE rating_games > 0;
UPDATE users SET rating = 1500 WHERE rating_games = 0;
```

### 0.2 Зөрчил №2 — нэг rating, хоёр тоглоом

`users.rating` нь шатар, даам **хоёуланд нэг**. Шатарт хүчтэй хүн даамд
шинэхэн байж мэднэ — тэр үед тоо нь аль алинд зөв биш.

**Санал:** `users.rating` -ыг **хаяхгүй**, шинэ `player_ratings` хүснэгтэд
нүүлгэнэ (§12). `users.rating` нь нэг миграцийн турш «шатрын rating»-ийн
хуулбар болж үлдэж, дараа нь устгагдана — эс тэгвэл rating уншдаг 20
гаруй газрыг нэг өдөрт засах шаардлагатай болно.

### 0.3 Зөрчил №3 — «Лиг» гэдэг үг ХОЁР зүйлийг нэрлэж байна

Одоогийн `LEAGUE_TIERS` (Хүрэл … Очир) нь **долоо хоногийн XP**-ээр
20 хүний бүлэгт хуваарилагддаг — өдөр тутам эргэж ирэхийг хөхиүлэх
механизм. Шаардлага нь «League = rating-аас».

**Санал (зөвлөж байна):** хоёуланг нь үлдээж, **нэрийг салгана**:

- **Долоо хоногийн лиг** (одоогийнх, XP) — *идэвх*. Хүүхдийг өдөр бүр
  эргүүлж ирүүлдэг гол зүйл; хасвал хамгийн хүчтэй зуршлын гогцоо алга
  болно.
- **Зэрэглэл** (шинэ, rating) — *хүч*. §9-д.

Хэрэв зөвхөн нэгийг үлдээх шийдвэр гарвал тэр нь **бүтээгдэхүүний**
шийдвэр бөгөөд `lib/tactiq/league.ts`, `/leaderboard`, амжилтын
`leagueTier` үзүүлэлт гурвыг хөндөнө.

### 0.4 Мэргэжлийн дүгнэлт — цагийн төрлөөр rating салгах уу?

**Одоо БОЛОХГҮЙ. Схемийг салгахад БЭЛЭН болгоно.**

Шалтгаан — статистик: Elo нь тоглолтын тоо хуримтлагдсан үед л утгатай.
8 rating (2 тоглоом × 4 хурд) болговол сурагч бүр 8 хэсэгт хуваагдаж,
тус бүр нь **үүрд provisional** (10 тоглолтод хүрэхгүй) байна. Lichess
хурдаар салгадаг нь өдөрт хэдэн зуун мянган тоглолт болдогтой холбоотой.

**Шийдэл:** `player_ratings` нь `(user_id, game_type, rating_type)`
түлхүүртэй. Одоо `rating_type = 'all'` **зөвхөн**. Хурдыг салгах нөхцөл:

> Тухайн (тоглоом, хурд) хосд **≥ 3 000 үнэлэгдсэн тоглолт** ба
> **≥ 200 тоглогч** 10+ тоглолттой болсон үед тэр хурдыг салгана.

Салгах үед шинэ rating нь `all`-ийн утгаас **үрсэлж** (seed) эхэлнэ:
`rating_type='blitz'` шинэ мөр нь `all`-ийн rating, харин
`games_played = 0` (provisional) болно — тэгснээр шилжилт нь алгуур.

## 2. МАТЕМАТИК

### 2.1 Гол томьёо

Хүлээгдэх оноо (expected score):

```
E = 1 / (1 + 10 ^ ((R_opp − R_player) / 400))
```

Үр дүн (actual score): `Win = 1`, `Draw = 0.5`, `Loss = 0`.

Шинэ rating:

```
R' = R + K × w × (S − E)
```

`w` нь **жин** (weight) — 0 < w ≤ 1. Ердийн тоглолтод `w = 1`; давтан
тоглолт, арена дахь дахин хос зэрэгт бууруулна (§5.4).

`400` гэсэн тоо нь Elo-гийн тодорхойлолт: 400 оноогоор давуу тоглогч
~10 дахин их магадлалаар ялна.

### 2.2 K коэффициент — санал болгож буй хувилбар

Шаардлагад 40/32/20 гэж байсныг **доорх байдлаар засав**:

| Нөхцөл | K | Шалтгаан |
| --- | --- | --- |
| `games < 10` (placement) | **50** | 40 бол 10 тоглолтод ±250 л хүрнэ — жинхэнэ хүч 1900 байсан хүүхэд placement-ээс 1750 гарч, дараа нь 30 тоглолт зарцуулна |
| `10 ≤ games < 30` | **32** | Шаардлагатай хэвээр |
| `games ≥ 30` | **20** | Шаардлагатай хэвээр |
| `rating ≥ 2200` (30+ тоглолттой) | **16** | Тэргүүний тоо нь найдвартай; нэг санамсаргүй хожигдол түүнийг хаях ёсгүй |
| `rating < 1100` (30+ тоглолттой) | **24** | Доод хэсэгт тоглогч хурдан хөгждөг (хүүхэд сурч байна) — K бага байвал rating нь хөгжлөөс хоцорно |

### 2.3 Өрсөлдөгчийн тодорхойгүй байдлыг дарах

**Provisional өрсөлдөгчтэй тоглоход тогтворжсон тоглогчийн K-г хагасална:**

```
if (opponent.gamesPlayed < 10) K_self × 0.5
```

Шалтгаан: provisional хүний 1500 гэсэн тоо нь **баримт биш, таамаг**.
Түүний эсрэг ялалтаас тогтворжсон тоглогч бүтэн оноо авбал шинэ хүнийг
«шүүх» болно. Provisional тал нь өөрийн бүтэн K-гаараа хөдөлсөөр байна —
тэр хөдлөх ЁСТОЙ.

### 2.4 Хязгаар

| Хязгаар | Утга | Шалтгаан |
| --- | --- | --- |
| Доод хязгаар (floor) | **800** | Үүнээс доош унасан хүүхэд «би чадахгүй» гэж бууна. 100 (одоогийн `MIN_RATING`) нь хэт доогуур — утга агуулгагүй |
| Дээд хязгаар | **байхгүй** | Хиймэл дээд хязгаар нь тэргүүний тоглогчдын ахицыг нуудаг |
| Нэг тоглолтын дээд өөрчлөлт | **±80** | Хамгаалалт: 2400 vs 800 гэсэн хачирхалтай хос үүсвэл (эсвэл манипуляци) нэг тоглолт 200 оноо хөдөлгөхгүй |
| Бөөрөнхийлөлт | **`Math.round`**, зөвхөн ХАДГАЛАХ мөчид | Дундын тооцоонд бөөрөнхийлвэл олон тоглолтын турш алдаа хуримтлагдана |

## 3. ТЭМЦЭЭНИЙ ЧАНСАА — ТУСДАА RATING БАЙХ УУ?

**Байхгүй.** Тэмцээний хэлбэр (arena / swiss / knockout / round robin /
team) нь **rating-ийн математикийг ОГТ өөрчлөхгүй**. Хэлбэр нь зөвхөн:

1. хос хэрхэн сугалагдахыг,
2. хэдэн тоглолт болохыг,
3. rating хэзээ шинэчлэгдэхийг (§4.3)

шийддэг. Тоглолт бүр нь 1v1 бөгөөд §2-ын томьёогоор үнэлэгдэнэ.

**Яагаад «Arena rating», «Swiss rating» гэж салгахгүй вэ:** тэд нэг л
зүйлийг (тоглолтын хүч) хэмждэг. Салгавал сурагч 4 тоо тээж, аль нь
«жинхэнэ» вэ гэдэг нь хэнд ч ойлгомжгүй болно. Оронд нь тэмцээний
**чансаагийн бүртгэл** (`rating_history.tournament_id`) нь «энэ тэмцээнд
хэд авсан» гэдгийг ямагт харуулж чадна.

**Харин `performance rating`** (тухайн тэмцээний үзүүлэлт) нь ХАДГАЛАГДАХ
rating БИШ, зөвхөн тэмцээний хүснэгтэд харуулах тоо:

```
Rp = (өрсөлдөгчдийн rating-ийн дундаж) + D(p),   p = авсан оноо / тоглолтын тоо
```

`D(p)` нь FIDE-ийн хүснэгт (p=1.0 → +800, 0.75 → +193, 0.5 → 0,
0.25 → −193, 0.0 → −800). Хэрэгжүүлэхдээ шугаман интерполяци хангалттай.

### 3.1 Одоогийн кодтой холбоо

| Хэлбэр | Rating шинэчлэлт | Хэрэгжүүлэх газар |
| --- | --- | --- |
| 1v1 (лобби, урилга) | **Тоглолт тус бүрд, ТЭР ДАРУЙ** | `/api/play/rooms/[id]/end` (аль хэдийн байгаа) |
| Arena | **Тоглолт тус бүрд, ТЭР ДАРУЙ** | Тэмцээний сервер → `/api/tournament/game` (шинэ) |
| Swiss, Round Robin, Knockout | **Тэмцээн дууссаны дараа НЭГ ДОР** | `/api/tournament/[id]/rate` (шинэ) |
| Team | Хувь хүний тоглолт бүр нь ердийн тоглолт | Swiss-тэй ижил |
| Ботын эсрэг | Rating-д **ОРОХГҮЙ** (§13.6) | `applyBotGame`-ийг өөрчилнө |

## 4. SWISS ТЭМЦЭЭНИЙ RATING

### 4.1 Тооцооллын дэс дараалал

```
Тэмцээн дуусахад:
  1. Тэмцээнд оролцсон бүх тоглогчийн ТЭМЦЭЭНИЙ ӨМНӨХ rating-ийг ав (R₀)
  2. Тоглолт бүрд:
       E = 1 / (1 + 10 ^ ((R₀_opp − R₀_self) / 400))      ← ЗӨВХӨН R₀
       Δ_i = K(self) × w_i × (S_i − E_i)
  3. Δ_total = Σ Δ_i
  4. R_new = clamp(R₀ + Δ_total, floor, ∞)
```

### 4.2 `R₀`-г хэрэглэх нь ГОЛ шийдвэр

Тэмцээний турш бүх тоглолтод **тэмцээний өмнөх** rating хэрэглэгдэнэ
(FIDE-ийн арга). Ингэснээр:

- **Дараалал нөлөөлөхгүй.** Round бүрийн дараа шинэчилбэл «хэн хэнтэй
  хэзээ тоглосон» нь үр дүнг өөрчилнө — ижил үр дүнтэй хоёр тоглогч өөр
  оноо авна.
- **Эрт ялалтыг «эзэмших» боломжгүй.** Round 1-д хүчтэйг хожоод rating
  өссөн тоглогч дараагийн round-уудад бага оноо авах нь шударга бус.
- **Тооцоо дахин ажиллуулж болно** (idempotent): оролт нь өөрчлөгддөггүй
  тул алдаа гарвал дахин тооцож ижил үр дүн гарна.

### 4.3 Round бүрийн дараа vs Тэмцээн дууссаны дараа

| | Round бүрийн дараа | Тэмцээн дууссаны дараа |
| --- | --- | --- |
| Сурагчийн мэдрэмж | Шуурхай хариу | Хүлээх (1-2 цаг) |
| Шударга байдал | Дараалал нөлөөлнө | Дараалал нөлөөлөхгүй |
| Хос сугалалт | Rating-аар хосолдог бол мэдрэмтгий | Нөлөөгүй |
| Дахин тооцох | Боломжгүй | Боломжтой |
| Хагас дуусах | Хагас оноо бичигдэнэ | Юу ч бичигдэхгүй |

**Daamal.org-д: тэмцээн дууссаны дараа НЭГ ДОР.** Swiss нь **онооны**
хосолдог (rating-аар биш) тул шуурхай шинэчлэх ач холбогдол алга, харин
шударга байдал нь чухал — эцэг эх «яагаад ижил үр дүнтэй хоёр хүүхэд өөр
оноо авав» гэж асуувал хариулах ёстой.

**Харин Arena нь эсрэг** (§5): тэнд тоглолт тасралтгүй урсдаг тул «дараа»
гэсэн мөч байхгүй.

### 4.4 Нэг тоглогч олон өрөг тоглосон үед

Swiss-д round тоо нь тогтмол (жишээ нь 7) бөгөөд тоглолт бүр
**бүрэн жинтэй** (`w = 1`). Ижил өрсөлдөгчтэй хоёр удаа тоглох нь
Swiss-д зохион байгуулалтын алдаа — гэхдээ хамгаалалт болгон §5.4-ийн
давтан жинг мөн хэрэглэнэ.

### 4.5 Bye (өрсөлдөгчгүй round)

**Rating-д ОГТ ОРОХГҮЙ.** Bye нь тэмцээний онооны механизм (1 оноо), харин
тоглолт биш. Rating нь зөвхөн бодит тоглолтоос гарна.

## 5. ARENA ТЭМЦЭЭНИЙ RATING

Arena: тогтоосон хугацаанд (жишээ нь 60 мин) тоглогчид тасралтгүй хос
сугалж, хэдэн ч тоглолт хийж болно.

### 5.1 Шинэчлэлт — ТОГЛОЛТ ТУС БҮРД, ТЭР ДАРУЙ

Шалтгаан: arena нь 60 минутын турш үргэлжилдэг бөгөөд «дараа» гэсэн мөч
нь тоглогчийн хувьд хэтэрхий хол. Мөн arena дахь хос сугалалт нь
**rating-аар** хийгддэг (§5.2) тул шинэ rating нь дараагийн хосыг зөв
болгоно.

### 5.2 Хос сугалалт (pairing)

```
Сул (тоглолтгүй) тоглогчдын дундаас:
  1. Хүлээж байсан хугацаагаар эрэмбэлнэ (хамгийн урт хүлээсэн нь эхлээд)
  2. Тэр тоглогчид ХАМГИЙН ОЙРХОН rating-тай сул тоглогчийг олно
  3. Гэхдээ СҮҮЛИЙН 2 өрсөлдөгчийг АЛГАСНА (боломжтой бол)
  4. Хос олдохгүй бол rating-ийн зөрүүний хязгаарыг 100 → 200 → ∞ тэлнэ
```

3-р дүрэм нь хоёр найз бие биетэйгээ дахин дахин тоглохыг таслана.
4-р дүрэм нь жижиг тэмцээнд (6 хүн) тоглогч хүлээж гацахаас сэргийлнэ.

### 5.3 Цуваа (streak), берсерк — RATING-Д ОРОХГҮЙ

Arena-д дараалсан 2 ялалт «гал» асааж, дараагийн ялалт **давхар оноо**
болдог; берсерк нь цагаа хагасалж +1 оноо нэмдэг. Эдгээр нь **тэмцээний
онооны** механизм — rating-д ОРОХГҮЙ.

Шалтгаан: rating нь «хэр сайн тоглодог» гэдгийг хэмждэг, харин цуваа нь
«хэр их эрсдэл авсан» гэдгийг хэмждэг. Хоёрыг холивол rating нь тоглоомын
хэлбэрээс хамааралтай болж, тэмцээн хоорондын харьцуулалт унана.

### 5.4 Давтан тоглолтын БУУРАХ ЖИН

Нэг arena дотор ижил хоёр тоглогч дахин тоглох үед:

| Уулзалт | `w` |
| --- | --- |
| 1-рт | 1.0 |
| 2-рт | 0.5 |
| 3-рт | 0.25 |
| 4+ | 0.1 |

Шалтгаан: 60 минутын arena-д хоёр хүн 15 удаа тоглож болно. Бүрэн жинтэй
бол тэд бүх арена нь тэдний хоёрын хоорондох «дуэль» болж, rating нь
бусад тоглогчдын талаар юу ч хэлэхгүй болно. Мөн §13.5-ийн хамгаалалт.

Жин нь **тухайн arena дотор** тоолно (хоёр өөр арена дахь уулзалт тус
тусдаа 1.0 жинтэй).

## 6. INFLATION / DEFLATION ХАМГААЛАЛТ

### 6.1 Асимметр K нь оноо ҮҮСГЭДЭГ

Хоёр тоглогч ижил K хэрэглэвэл Elo нь **тэг нийлбэртэй** (`Δ_A = −Δ_B`).
Гэвч §2.2-оор provisional (K=50) ба тогтворжсон (K=20) тоглогч тоглоход
нийлбэр нь тэг биш — систем оноо **үүсгэж** эсвэл **устгаж** байна.

**Шийдвэр: асимметрыг зөвшөөрнө** (энгийн байдлын төлөө), харин доорх
гурван механизмаар тэнцвэржүүлнэ:

### 6.2 Placement-ийн оноо тусгаарлалт

Placement-ийн үед (`games < 10`) тоглогчийн **өрсөлдөгч** нь буурсан
K (×0.5) авдаг (§2.3). Энэ нь шинэ тоглогч системд хэт их оноо
шахахыг хязгаарлана.

### 6.3 Decay (хөдөлгөөнгүйн бууралт)

```
if (өдөр 90+ тоглоогүй) AND (rating > 1700):
    сар бүр −25, гэхдээ 1700-аас доош БУУРАХГҮЙ
```

Зөвхөн 1700-аас дээш: доод, дунд хэсгийн хүүхэд хэдэн сар завсарлаж
болно (хичээлийн амралт), тэднийг шийтгэх шалтгаан алга. Харин тэргүүний
жагсаалтыг тоглодоггүй хүн эзэлж байх нь бусдын хөшүүргийг унагана.

**Decay нь rating-ийн түүхэнд `reason = 'decay'` гэж бичигдэнэ** — эс
тэгвэл тоглогч «яагаад буурав» гэдгийг хэзээ ч мэдэхгүй.

### 6.4 Хэт зөрүүтэй хосыг үнэлэхгүй

```
if |R_A − R_B| > 600: тоглолт RATING-Д ОРОХГҮЙ (найрсаг тоглолт)
```

Шалтгаан: 600+ зөрүүтэй үед E ≈ 0.97 бөгөөд ялалт нь ~0.6 оноо л өгнө —
харин **сул талын хожил** нь 19 оноо авна. Энэ тэнцвэргүй байдал нь
«сул хаягтай тоглож оноо цуглуулах» схемийн үндэс болдог.

### 8.1 Жагсаалтууд

| Жагсаалт | Шүүлт | Хамгийн бага тоглолт |
| --- | --- | --- |
| Global | (game_type, rating_type) | **10** |
| Улс | `users.country` | 10 |
| Аймаг / хот | `users.province` | 10 |
| Нас (U8, U10, U12, U14, U16, 17+) | `users.birth_year` | 10 |
| Долоо хоног | `rating_history` дахь **өөрчлөлтийн нийлбэр** | 5 (тэр долоо хоногт) |
| Сар | мөн адил | 10 (тэр сард) |
| Тэмцээн | `rating_history.tournament_id` | — |

### 8.2 «Давхар тоолохгүй» — эндүүрлийг тодруулъя

Leaderboard нь **rating-ийг тооцдоггүй**, зөвхөн **уншдаг**. Тиймээс нэг
тоглогч 6 жагсаалтад зэрэг байснаас rating-д ямар ч давхардал үүсэхгүй.

Давхардлын жинхэнэ эрсдэл нь өөр газар:

1. **Нэг тоглолтыг хоёр удаа бичих** — `rating_history` дээр
   `UNIQUE (game_id, user_id)` индексээр таслана. `game_id` нь өрөөний
   id эсвэл arena-гийн тоглолтын id.
2. **Долоо хоног/сарын жагсаалт** нь `rating_history`-гоос **нийлбэр**
   тооцдог тул тэр хүснэгт давхардвал тоо хоёр дахин болно. Дээрх
   индекс нь үүнийг ч барина.

### 8.3 Хэрэгжүүлэх тэмдэглэл

Долоо хоногийн жагсаалтын асуулга (`SUM(rating_change)`) нь индексгүй бол
хүснэгт өсөхөд удаашрана:

```sql
CREATE INDEX rating_history_user_created_idx
  ON rating_history (user_id, created_at DESC);
CREATE INDEX rating_history_created_idx
  ON rating_history (created_at DESC);
```

## 11. ТООН ЖИШЭЭНҮҮД

### 11.1 Дөрвөн тоглогчийн тэмцээн (§11-ийн шаардлага)

**Оролт:** A=1500, B=1600, C=1700, D=1400. Бүгд 30+ тоглолттой → K=20.
Swiss тул **тэмцээний өмнөх** rating хэрэглэгдэнэ (§4.2).

A-ийн тоглолтууд: B-тэй **хожсон**, C-тэй **хожигдсон**, D-тэй **тэнцсэн**.

| Тоглолт | E (A-ийн) | S | Δ_A |
| --- | --- | --- | --- |
| A vs B (1600) | 1/(1+10^0.25) = 0.3599 | 1 | **+12.80** |
| A vs C (1700) | 1/(1+10^0.50) = 0.2403 | 0 | **−4.81** |
| A vs D (1400) | 1/(1+10^−0.25) = 0.6402 | 0.5 | **−2.80** |

```
Δ_A = +12.80 − 4.81 − 2.80 = +5.19  →  A = 1505
```

Өрсөлдөгчид (тус бүр нэг тоглолттой):

| Тоглогч | E | S | Δ | Шинэ |
| --- | --- | --- | --- | --- |
| B | 0.6401 | 0 | −12.80 | **1587** |
| C | 0.7597 | 1 | +4.81 | **1705** |
| D | 0.3598 | 0.5 | +2.80 | **1403** |

**Шалгалт (тэг нийлбэр):** `+5.19 − 12.80 + 4.81 + 2.80 = 0.00` ✓

### 11.2 Том тэмцээнүүд

| Тоглогч | Хэлбэр | Round | Нэг хүний тоглолт | Нийт тоглолт | Rating-ийн шинэчлэлт |
| --- | --- | --- | --- | --- | --- |
| 8 | Round Robin | 7 | 7 | 28 | Дууссаны дараа, 28 бичилт |
| 16 | Swiss | 5 | 5 | 40 | Дууссаны дараа, 40 бичилт |
| 32 | Swiss | 6 | 6 | 96 | Дууссаны дараа, 96 бичилт |
| 64 | Knockout | 6 | 1–6 | 63 | Дууссаны дараа, 63 бичилт |
| 64 | Arena (60 мин) | — | ~8–14 | ~350 | **Тоглолт тус бүрд**, давтан жинтэй |

**Knockout-ийн онцлог:** эрт хасагдсан тоглогч 1 тоглолт л хийнэ. Тэр нэг
тоглолт бүрэн жинтэй үнэлэгдэнэ — «эрт гарсан тул хөнгөвчилье» гэж
болохгүй, тэгвэл knockout нь rating-д хямд эрсдэл болж хувирна.

## 12. САНГИЙН БҮТЭЦ

### 12.1 `player_ratings`

```sql
CREATE TABLE player_ratings (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       varchar(128) NOT NULL,
  -- "chess" | "checkers"
  game_type     varchar(16)  NOT NULL,
  -- ОДОО зөвхөн 'all'. Хожим: 'classical' | 'rapid' | 'blitz' | 'bullet' (§0.4)
  rating_type   varchar(16)  NOT NULL DEFAULT 'all',

  rating        integer NOT NULL DEFAULT 1500,
  peak_rating   integer NOT NULL DEFAULT 1500,
  games_played  integer NOT NULL DEFAULT 0,
  wins          integer NOT NULL DEFAULT 0,
  draws         integer NOT NULL DEFAULT 0,
  losses        integer NOT NULL DEFAULT 0,
  last_game_at  timestamptz,
  updated_at    timestamptz NOT NULL DEFAULT now(),

  -- Нэг хүн, нэг тоглоом, нэг төрөлд НЭГ мөр
  CONSTRAINT player_ratings_uq UNIQUE (user_id, game_type, rating_type)
);

CREATE INDEX player_ratings_board_idx
  ON player_ratings (game_type, rating_type, rating DESC)
  WHERE games_played >= 10;   -- leaderboard нь provisional-ийг хардаггүй
```

**`provisional` багана БАЙХГҮЙ**: `games_played < 10` гэдгээс гарна. Хоёр
эх сурвалж байвал тэд зөрөх бөгөөд аль нь зөв гэдгийг хэн ч мэдэхгүй.

### 12.2 `rating_history`

```sql
CREATE TABLE rating_history (
  id             uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id        varchar(128) NOT NULL,
  game_type      varchar(16)  NOT NULL,
  rating_type    varchar(16)  NOT NULL DEFAULT 'all',

  -- Аль тоглолт: өрөөний id, эсвэл arena-гийн тоглолтын id
  game_id        varchar(64),
  -- Аль тэмцээн (байвал) — тэмцээний чансааны тайланд
  tournament_id  varchar(64),

  opponent_uid   varchar(128),
  opponent_rating integer,
  -- 1 | 0.5 | 0
  result         numeric(2,1),
  expected_score numeric(6,5) NOT NULL,
  k_factor       integer NOT NULL,
  weight         numeric(3,2) NOT NULL DEFAULT 1.0,

  old_rating     integer NOT NULL,
  rating_change  integer NOT NULL,
  new_rating     integer NOT NULL,

  -- "game" | "tournament" | "decay" | "admin"
  reason         varchar(16) NOT NULL DEFAULT 'game',
  created_at     timestamptz NOT NULL DEFAULT now()
);

-- ДАВХАР БИЧИЛТИЙГ ТАСЛАНА (§8.2)
CREATE UNIQUE INDEX rating_history_game_user_uq
  ON rating_history (game_id, user_id)
  WHERE game_id IS NOT NULL;

CREATE INDEX rating_history_user_created_idx ON rating_history (user_id, created_at DESC);
CREATE INDEX rating_history_created_idx      ON rating_history (created_at DESC);
CREATE INDEX rating_history_tournament_idx   ON rating_history (tournament_id);
```

**Яагаад `expected_score`, `k_factor`, `weight`-ийг ХАДГАЛНА:** «яагаад
би 12 оноо авав?» гэсэн асуултад **тооцоог дахин хийхгүйгээр** хариулах
ёстой. K-ийн дүрэм хожим өөрчлөгдвөл хуучин бичилтүүд нь тухайн үеийн
дүрмээр л тайлбарлагдана.

### 12.3 Миграцийн дараалал

```

...   (кодыг шилжүүлсний дараа)
00NN_drop_users_rating.sql   -- users.rating, users.rating_games хасах
```

`0049`-ийн агуулга:

```sql
INSERT INTO player_ratings (user_id, game_type, rating_type, rating, peak_rating, games_played, wins, draws, losses)
SELECT uid, 'chess', 'all',
       CASE WHEN rating_games > 0 THEN rating + 300 ELSE 1500 END,
       CASE WHEN rating_games > 0 THEN rating + 300 ELSE 1500 END,
       rating_games, chess_wins, chess_draws, chess_losses
FROM users
ON CONFLICT DO NOTHING;

INSERT INTO player_ratings (user_id, game_type, rating_type, rating, peak_rating, games_played, wins, draws, losses)
SELECT uid, 'checkers', 'all', 1500, 1500, 0, draughts_wins, draughts_draws, draughts_losses

```

үүсгэнэ. Даамын ялалт/хожигдлын тоог харин хадгална (түүх).

## 13. ANTI-CHEAT

| Заналхийлэл | Хамгаалалт |
| --- | --- |
| **Sandbagging** (зориуд хожигдож rating бууруулах) | Rating floor 800; 30 хоногт 5+ «хачирхалтай хожигдол» (E > 0.9 үед хожигдох) бүртгэгдвэл тэмдэглэж, админд мэдэгдэнэ |
| **Хоёр хаяг** (өөртэйгөө тоглох) | Ижил IP / төхөөрөмжийн хос тоглолт нь `weight = 0` (үнэлэгдэхгүй); §5.2-ын «сүүлийн 2 өрсөлдөгчийг алгасах» дүрэм |
| **Давтан тоглолт** (нэг хосоос оноо цуглуулах) | §5.4-ийн буурах жин; мөн 24 цагт ижил хосын 10+ тоглолт → `weight = 0.1` |
| **Account sharing** (хүчтэй хүн бусдын хаягаар) | Rating-ийн гэнэтийн үсрэлт (30 хоногт +300 ба 20+ тоглолт) → тэмдэглэгээ; placement-ийг дахин шаардах боломж |
| **Хөдөлгүүр (engine)** | Энэ баримтын гадна — тусдаа систем (нүүдлийн хугацааны тархалт, төгс нүүдлийн хувь). Rating систем нь зөвхөн **тугийг** уншина: `users.rating_frozen = true` үед бичилт хийхгүй |
| **Ботоос оноо** | Ботын тоглолт rating-д **ОРОХГҮЙ** (§13.6) |
| **Тэмцээнээс гарах** (хожигдох гэж байхад) | Гарсан тоглолт нь **хожигдол** гэж бичигдэнэ (тэмцээний серверийн дүрэм) |

### 13.6 Ботын тоглолт — rating-д орох уу?

**ОРОХГҮЙ.** Одоогийн код (`applyBotGame`) ботын эсрэг тоглолтоор rating
өөрчилдөг. Үүнийг **зогсоох** санал:

- Ботын хүч нь `SEARCH_DEPTH`-аас хамаардаг бөгөөд код өөрчлөгдөхөд
  чимээгүй өөрчлөгдөнө — тэр үед бүх хуучин rating буруу болно.
- Бот нь хязгааргүй тоглодог: сурагч 200 тоглолт хийж rating-аа хүссэн
  хэмжээнд хүргэж чадна.
- Оронд нь ботын эсрэг үр дүн нь **XP, амжилт, ур чадварын** хэсэгт
  бичигдэнэ (тэр нь аль хэдийн байдаг).

Ботын rating (`BOT_RATINGS`) нь **зөвхөн харагдацад** үлдэнэ: «Та 1600
хүчтэй ботыг яллаа».

## 15. PSEUDOCODE

### 15.1 Нэг тоглолт

```ts
async function rateGame(input: {
  gameId: string;
  gameType: "chess" | "checkers";
  ratingType: string;          // одоогоор "all"
  white: { uid: string; score: 1 | 0.5 | 0 };
  black: { uid: string; score: 1 | 0.5 | 0 };
  tournamentId?: string;
  /** Тухайн тэмцээн дотор ижил хос хэд дэх удаа тоглож байна (0-ээс) */
  rematchIndex?: number;
}) {
  return db.transaction(async (tx) => {
    // ⚠ ИДЕМПОТЕНТ: дахин илгээгдсэн хүсэлт rating-ийг хоёр дахин хөдөлгөхгүй
    if (await tx.historyExists(input.gameId)) return "already-rated";

    // ⚠ ХОЁУЛАНГ НЬ ТҮГЖИНЭ, ижил дарааллаар (uid-аар эрэмбэлж):
    //    эс бөгөөс хоёр зэрэг тоглолт deadlock үүсгэнэ
    const [a, b] = await tx.lockRatings(
      [input.white.uid, input.black.uid].sort(),
      input.gameType,
      input.ratingType
    );

    if (a.frozen || b.frozen) return "frozen";

    // §6.4 — хэт зөрүүтэй хосыг үнэлэхгүй
    if (Math.abs(a.rating - b.rating) > 600) return "unrated-gap";

    const w = rematchWeight(input.rematchIndex ?? 0);   // §5.4
    const changes = [];

    for (const [self, opp, score] of [
      [a, b, scoreOf(a.uid, input)],
      [b, a, scoreOf(b.uid, input)],
    ]) {
      const E = 1 / (1 + 10 ** ((opp.rating - self.rating) / 400));
      let K = kFactor(self.gamesPlayed, self.rating);       // §2.2
      if (opp.gamesPlayed < 10) K *= 0.5;                   // §2.3

      const raw = K * w * (score - E);
      const delta = Math.round(clamp(raw, -80, 80));        // §2.4

      const next = Math.max(800, self.rating + delta);

      changes.push({ self, E, K, w, score, delta, next });
    }

    for (const c of changes) {
      await tx.updateRating(c.self.uid, {
        rating: c.next,
        peakRating: Math.max(c.self.peakRating, c.next),
        gamesPlayed: c.self.gamesPlayed + 1,
        wins: c.self.wins + (c.score === 1 ? 1 : 0),
        draws: c.self.draws + (c.score === 0.5 ? 1 : 0),
        losses: c.self.losses + (c.score === 0 ? 1 : 0),
        lastGameAt: now,
      });
      await tx.insertHistory({ ...c, gameId: input.gameId, reason: "game" });
    }

    return "rated";
  });
}
```

### 15.2 Тэмцээн (Swiss / RR / KO)

```ts
async function rateTournament(tournamentId: string) {
  const games = await loadGames(tournamentId);       // дуусгавартай бүх тоглолт
  const uids = unique(games.flatMap((g) => [g.whiteUid, g.blackUid]));

  // §4.2 — ТЭМЦЭЭНИЙ ӨМНӨХ rating (R₀). Тоглолт бүрд ижил утга.
  const before = await loadRatings(uids);

  const totals = new Map<string, number>();
  const rows = [];

  for (const g of games) {
    for (const [self, opp, score] of sides(g)) {
      const R0 = before.get(self)!;
      const R0opp = before.get(opp)!;

      if (Math.abs(R0.rating - R0opp.rating) > 600) continue;   // §6.4

      const E = 1 / (1 + 10 ** ((R0opp.rating - R0.rating) / 400));
      let K = kFactor(R0.gamesPlayed, R0.rating);
      if (R0opp.gamesPlayed < 10) K *= 0.5;

      const w = rematchWeight(g.rematchIndex);
      const delta = clamp(K * w * (score - E), -80, 80);

      totals.set(self, (totals.get(self) ?? 0) + delta);
      rows.push({ self, opp, E, K, w, score, delta, gameId: g.id, tournamentId });
    }
  }

  // ⚠ НЭГ ГҮЙЛГЭЭНД: тэмцээний оноо хагас бичигдэх нь хамгийн дор
  await db.transaction(async (tx) => {
    for (const [uid, delta] of totals) {
      const R0 = before.get(uid)!;
      const next = Math.max(800, R0.rating + Math.round(delta));
      await tx.updateRating(uid, { rating: next, ... });
    }
    await tx.insertHistoryBatch(rows.map((r) => ({ ...r, reason: "tournament" })));
  });
}
```

### 15.3 Decay (сар бүр нэг удаа)

```ts
async function applyDecay(now = new Date()) {
  const idle = await db.ratingsIdleSince(daysAgo(now, 90));   // rating > 1700
  for (const row of idle) {
    const months = monthsSince(row.lastGameAt, now);
    const target = Math.max(1700, row.rating - 25 * months);
    if (target === row.rating) continue;

    await db.updateRating(row.userId, { rating: target });
    await db.insertHistory({ ...row, newRating: target, reason: "decay" });
  }
}
```

## 16. EDGE CASE-УУД

| Тохиолдол | Хэрхэн шийдэх |
| --- | --- |
| Тоглолт **хагас** тасарсан (холболт унасан) | Тэмцээний серверийн дүрмээр хожигдол/тэнцээ гэж шийдэгдсэн бол ердийн тоглолт. Шийдэгдээгүй бол **rating-д ОРОХГҮЙ** |
| Хоёр тал **зэрэг** «би ялсан» гэж мэдэгдэх | `game_id` unique индекс — эхнийх бичигдэж, хоёрдугаарт `already-rated` |
| Өрсөлдөгч rating-гүй (шинэ хаяг, мөр байхгүй) | Мөрийг 1500-аар **үүсгээд** үргэлжилнэ (`ON CONFLICT DO NOTHING` + дахин унших) |
| Rating floor дээр хожигдох | `delta` нь 0 болно, гэхдээ `games_played`, `losses` **өснө** — тоглолт болсон нь баримт |
| Tournament дунд хаяг хөлдөөгдөх | `rateTournament` нь тэр тоглогчийн бичилтийг алгасна, бусдын тооцоонд түүний R₀ хэрэглэгдсээр байна |
| K-ийн дүрэм өөрчлөгдөх | Хуучин бичилтүүд **дахин тооцогдохгүй** (түүх нь тухайн үеийн дүрмийн баримт). Дахин тооцох шаардлагатай бол `/api/admin/ratings/recalculate` |
| Ижил хоёр тоглогч өөр **тэмцээнд** дахин уулзах | Жин нь тэмцээн тус бүрд шинээр (1.0-аас) тоолно |
| Тоглогч **насны бүлэг** солих (төрсөн өдөр) | Насны жагсаалт нь `birth_year`-оос **асуулгын үед** тооцогдоно — хадгалагдсан бүлэг байхгүй |
| Хугацаа дуусахад **хоёулаа** цаг барьсан | Тэнцээ (S = 0.5 хоёуланд) |
